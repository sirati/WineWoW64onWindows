Fixes in this candidate

- Message times (d52c62d, patch 0011). The renderer bridge dropped its own
  clicks as "posted 4294967287 ms ago": the in-process server stamped
  messages from precise interrupt time while clients read the native shared
  tick count. The server's get_tick_count now uses that tick count, which
  keeps Wine's guarantee that a received message is not newer than the
  receiver's GetTickCount. The bridge's first-run Preferences click now
  opens Preferences.
- Thread TEBs (85362a3). A new guest thread's TEB was a copy of the first
  thread's, so ReservedForOle, COM's per-thread data, was shared. A thread
  that exited freed it under the main thread; Civ3 then faulted in
  combase CoRegisterInitializeSpy (+0xC286, reading 0xB) when imm32
  activated the IME window, and Wine's dispatch_user_callback ignored the
  access violation. New TEBs now start zeroed, as in Wine's init_teb.
- Native library names (a45c205). The loader refuses a unixlib or companion
  whose name matches a System32 DLL; Windows would bind other modules'
  imports of that DLL to it.
- NtFlushInstructionCache uses Wine's wow64 thunk (e3a6279). A failed guest
  user callback is reported with its id and arguments (6fd232d).
