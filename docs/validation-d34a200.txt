Current limits

CET remains incompatible with Wine's IRETQ restore, which previously produced
c0000409 / FAST_FAIL_CONTROL_INVALID_RETURN_ADDRESS, 0x39. A standalone
NtContinue diagnostic requested CS=0x23 but observed CS=0x33 at its trap on
this Windows build. It therefore does not provide a compatibility-mode
replacement for IRETQ. Single-step tests must check the code segment as well
as the instruction pointer. The diagnostic's status 20 means its requested
32-bit transition was not observed; it is not a runtime regression.

Canonical bootstrap-address collisions cause an explicit startup failure.
There is no fallback which rewrites executable pages. Relocation of normal
application images and DLLs remains Wine's responsibility. GUI, ARM64 and
additional NT services are excluded. The tested corpus does not establish
universal unmodified application compatibility.

Raw evidence remains outside Git in the frozen worktree's evidence directory:
candidate-files.json, vm-test-bundle.zip, nix-path-info.json,
vm-results/candidate-verification.txt and vm-results/results/. The result JSON
files contain command lines, native controls, exits, timeouts and output.
bootstrap-smoke includes queried policy flags and mapped DLL addresses.
continuation-revised contains the independent NtContinue traces.

Later documentation and test-helper commits do not change the implementation.
Nix rebuilds can embed an output-derived compiler seed in .debug_info and
therefore produce a different PE checksum and whole-file hash. The 342d360
rebuild was compared with this frozen candidate: changed PE sections were
limited to .debug_info. Executable and runtime data sections were unchanged.
The hashes above identify the actual frozen VM inputs, not arbitrary later
documentation rebuilds.
