The 7za, Lua and SQLite collision controls each deliberately occupied
0x00400000. All three pinned EXEs set IMAGE_FILE_RELOCS_STRIPPED and have
an empty relocation directory. Wine's original relocator returned c0000018;
the host reported Windows error 487. These are not relocatable executables.
Their normal unmodified executions pass in the full 22ec829 regression.

Unsafe wait-entry termination remains a separate observed failure. On
5d34797, three of fifty debugger runs self-exited 98 after dumping timeout
stacks. One surviving main thread was waiting on files_lock through
get_file / duplicate_wait_handle / probe_NtWaitForSingleObject. Its native
lock argument matched the mapped files_lock address. Two others blocked
while logging a service result through native CRT stderr. The ready event
does not prove that the worker has finished all adapters or reached its
kernel wait. The spin-mode control publishes readiness after those calls
return. It verifies cancellation/publication lifetime but does not resolve
termination while an adapter or native CRT lock is held.

The full accepted regression is in validation-22ec829.txt. CET remains open;
see cet-investigation.txt. The optional nested C++ returning-helper diagnostic
still fails in upstream Wine 11 as well as this port.
