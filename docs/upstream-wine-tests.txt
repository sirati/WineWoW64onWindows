Protected syscall integration

The later kernel32 thread crash reads NULL while Wine converts a
GROUP_AFFINITY32 for NtSetInformationThread. The test deliberately supplies
NULL and expects STATUS_ACCESS_VIOLATION. The fault is in original
wow64/process.c:1062, host RVA 0x1c942 on the verified 0ea4f04 candidate.
Wine normally catches such faults in its wow64_syscall SEH wrapper. The port
had called the thunks directly. The next change extracts that original
wrapper, handler and invalid-handle dispatcher helper, and uses native
RtlUnwind to return status before releasing temporary conversion storage.

The native thunk translation units need unwind information for that handler
to walk their frames. Enabling it also retains unused functions through
COFF .pdata references. The cross build therefore selects only the original
supported thunk definitions, preserving helpers, bodies and upstream line
numbers. It does not introduce stubs or additional guest services. Static PE
inspection verifies unwind ranges for the protected wrapper and the two
focused fault paths. The Windows results below establish focused recovery.
